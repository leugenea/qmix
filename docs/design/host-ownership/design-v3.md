## 2. One actual authoritative admission gate

Choose one process gate **G**, replacing host H and queue admission Q for all hosting-connected authorities. There is no H→Q or Q→H: H/Q cease to be independent monitors. QueueMutationContext remains a scheduling/affinity facility, not an authority lock or synchronous bridge. Its run/dispatch/wait occurs outside G; callbacks cannot run in a G state phase. No G holder acquires application provider lock, engine/library lock, or persistence lock; providers release their lock before invoking a factory. Completion handlers and public producers may acquire G for finite bookkeeping only.

G protects the **actual** host navigation/foreground claims, queue selection/latestRoom/pending/ended-consumption/worker slot, playback preparation/current-selection/foreground/mode/worker reservations, and ledger. No host cache computes coordinator eligibility. Every writer listed in matrix §1 participates, including synchronization, foreground recovery, queue reconciliation, retry/conflict, null selection, callbacks, close and navigation publication. Mutable coordinator authority is not left on the dispatcher while only a token getter uses G.

Each entry has two phases: under G validate identities, change domain state, reserve resources, and store a fixed immutable emission descriptor; after unlock select/publish/execute it. No observer, result factory, receipt completion, completion-handler registration, Job birth/cancel/start, factory, engine/network call, dispatcher dispatch/wait or persistence runs under G. Public `state` remains the published immutable snapshot; navigation decisions use the same host authority's committed version, not a second eligibility model. Coordinator pure state helpers may call one another under G; those calls cannot emit, launch or invoke supplied functions.

**Queue two-phase transaction:** prepare under G validates real queue semantics and captures session, foreground, queue-selection and preparation identities; it tentatively reserves one exact queue Pending, N operation and W credit. No ended-consumed flag becomes irrevocable yet. Release G. Only a bounded post request/receipt linkage may intervene, not a coordinator callback or factory. Commit under G rechecks all captured authority, host End/Stop, capacity ownership and posting disposition. The commit simultaneously marks queue acceptance, consumes this preparation's ENDED once, and makes the operation ready. **True linearizes here**, not at offer or worker entry; later cancellation is allowed. Failure discards only this transaction's Pending and charges, restoring ended eligibility only for its still-current, never-started selection. An unpublished older rollback cannot clear a newer Pending or ended flag. Posting after commitment can fail: the already accepted receipt becomes cancelled and hosting seals; this does not retroactively change true into a fabricated completion claim. Physical/birth loans prevent premature credit recycling.

Back/overlay is the same pure reserve/commit rule with an exact overlay version or terminal navigation reason; committed dismissal is visible to a second Back even before publication. Settings/create/warning claims reserve capacities and the room's DELETE allowance atomically. Warning confirmation performs its established synchronous durable-save exception outside G, then backvalidates its exact claim before true. Cancellation cannot steal that save claim; End revokes unstarted traffic. An End-winning confirmation returns false after durable save; a committed confirmation returns true even if subsequently cancelled. This particular return ordering is a **proposed linearization choice requiring owner decision**, not a claim that v1 established historical equivalence. No actor join, future wait or Main pumping is introduced.

### Coherent identity at both deferred boundaries

At OUTER public pause/resume/toggle/seek/retry admission, G reads the actual playback `PreparationId` plus session/foreground/effect identity and stores it with the command. The same G covers all preparation writers. Replacement, null, retry/reprepare and foreground invalidation retire identity; metadata-only refresh preserves it. Host→coordinator admission compares that exact token, never substitutes current textual track ID. An intentionally admitted retry creates a new ID in its own state phase, and its downstream continuations use that produced ID.

At INNER continuation admission and on the actual execution lane immediately before prepare/play/pause/seek/report, validate the command's produced/captured ID and epochs. A pure G activation claim is the effect-start linearization: Stop/End before that claim suppresses the call; after it the selected loan is already in flight and cancellation/disposal remains owed. No dispatch/suspension may intervene between claim and invocation. This does not promise physical transport entry is atomic with concurrent producer Stop: that stronger guarantee is impossible with arbitrary external callouts and no calls under G; a different physical-entry contract would require an owner-approved API/adapter change. Prepare→play cannot recapture latest selection. Queued B/A reductions that have not committed do not change authority; once they commit they invalidate old A, even before publication. Engine callbacks carry the preparation association installed for that exact prepare; textual media ID alone is inadequate. Metadata-positive controls must succeed. Callback payload/mode changes are sequenced within their existing record, not fresh identities used to rescue stale work.

## 3. Closed ledger and acknowledgement protocol

`ProcessHostOwner` is an application/process object, not an Activity/controller field. All production constructors, `hostSessionForActivity`, coordinator/publisher factories, test controller composition and provider overrides receive the **same** holder for a given process fixture. Production has no fresh per-controller default. Activity recreation, provider removal, Setup and controller cancellation never reset charges or seal. Tests may create a new isolated process fixture only after proving the old fixture fully settled, or intentionally retain its quarantined holder; reset cannot erase debt. The process playback engine is a single borrowed root resource; room playback does not release it.

Finite pools are proposed constants: N=64 optional operations, W=8 ordinary workers, O=4 create/observe/recover/join owners, T=2 finalizers, P=2 PAUSED records, D=8 DELETE allowances, R=2 room lifetime records, L=8 fixed claims/control records. **98 records**, each with one value cell, one raw terminal cell, one acknowledgement/receipt cell and at most eight simultaneous typed continuation descriptors. These are structural ceilings, not verified metrics. The matrix enumerates family-specific loans, resources, children and reuse; no symbolic F/R remains. Conservative adapter-owned ceiling is **176 charged ownership slots**, not a heap-object count: each Job slot bundles exactly one Job and at most one owned completion-registration handle; other slots own one declared handle/Call/response/listener/channel. Exact bundle mapping is in matrix §3; only actual borrowed aliases are excluded. The count corrects v2’s 175 by including the source-visible owned process-parent completion registration: its Job is borrowed, but the registration belongs to the existing fixed L seal owner and cannot be dismissed as an alias. The amended repository adds at most 71 queued/producer-held command/event payloads per observation owner: aggregate cells/payloads ≤578; continuations ≤784. Byte sizes, library-internal task/allocation counts, transport buffers and external observers are not proved bounded by these counts. The fixed native callback record accepts one sequenced value; if a non-backpressurable new callback finds that cell still owned by prior continuations, the proposal explicitly seals/cancels hosting rather than silently conflating or dropping accepted events. This callback-saturation policy is a new fail-closed choice needing owner approval and native viability proof. Uncooperative injected factories must obey declared allocation maxima or are outside the guarantee.

Record phases are Reserved→Running→Cancelling→Terminal; Reserved can cancel without birth. Running includes an attached but not-entered lazy child. Terminal is a Job/subtree fact, **not** resource retirement. Every birth has an existing record and birth-in-flight charge before external launch; attach the returned Job, then register completion/start outside G. Cancellation during launch retains the record until attachment/terminal. Skipped lazy starts are explicitly cancelled. Incomplete old workers occupy their slot through NonCancellable cleanup; a successor cannot overwrite them.

### Multi-result reuse and secondary notification sentinel

**STREAM/INTERMEDIATE delivery is unchanged.** A worker delivers `(operation, sequence, STREAM)` into its one value cell. Sequence s remains owned after reduction: publication, coordinator updates, collection/engine actions and secondary callbacks use that record's eight descriptors. ACK(s) occurs only when all s continuations have completed or been individually invalidated and their selected loans returned. It is not reduction acknowledgement. Only then may that existing worker resume and supply s+1; no extra sender/continuation coroutine is born. An intermediate descriptor must not require this producer's own terminal; that would be the same forbidden cycle, not a reason to weaken STREAM backpressure.

**FINAL handoff is different from final ACK and retirement.** After all earlier STREAM ACKs, the same worker invokes a finite non-suspending `handoffFinal(operation, s, value, typedDescriptors)`. Under G it checks the exact owner/generation and vacant value cell, installs the last value and bounded descriptors, sets `lastSequence=s/noMoreSequences`, and commits either `RETAINED` or `CANCELLED_RETAINED`. The returned handoff receipt is a disposition enum plus owner/sequence identity, not a new future/Job/record and not business success. After unlock it requests only bounded non-inline posting; rejection seals/cancels and claims neutral discard, without waiting for Main, reduction, continuation, final ACK or whole-Job terminal. The call returns a finite receipt; the producer releases its local references, proceeds through its original finally/structured children, and cannot emit s+1 or launch more business work. Same-sequence retry is an idempotent lookup of the original receipt; another sequence is a protocol violation that seals/cancels, never a new accepted result. A retained receipt proves only ownership transfer, even if posting/cancellation wins before the caller observes its return. Producer `finally/close` closes only its emission endpoint/idempotent producer-done fact; it must not recycle the value cell, release credit or await final ACK.

The exact owner retains the value, all unfinished descriptors and original birth/resource/physical loans. `finalACK(s)` uses the original full-continuation ACK rule; handoff does not satisfy it. It may precede terminal only if all descriptors are completed/discarded and selected loans returned without needing terminal; terminal-dependent descriptors remain blocked until the exact full Job/subtree fact is recorded. The existing ACK/receipt cell is a fixed tagged structure with handoff disposition, ACK/discard bit and exactly-once settlement claim, not two independently allocated deferreds. Handoff receipt return never frees that cell, N/W/O/T/P/D/R credit, ring position or physical slot. Retirement is conjunctive: full Job terminal accounted AND final ACK/discard AND no birth/selected/transport callback/response loan AND successful required physical disposition. The independent raw terminal cell can coexist with the retained value; neither cell overwrites the other.

Cancellation before handoff fixes `CANCELLED_RETAINED`: if final code arrives it records the same no-more-sequences tombstone and no domain continuation becomes eligible; if the body never arrives, terminal/cancellation accounting closes the absent-value path, not a fabricated successful handoff. Cancellation after retained handoff claims final discard once, suppresses unstarted descriptors and leaves already selected work/physical loans charged. All receipt/ACK notifications happen outside G; neutral discard may settle off-lane, but no affine charge is released by it. Completion registration is charged before birth, installed outside G and combined into one handler per Job slot (§3), not a new join/sender Job.

Non-rejected POST-result→GET-birth admission→GET-result is one W owner: intermediate POST and GET-birth deliveries keep full STREAM ACK; nested GET child is a charged subslot, not another W or N record. Rejected POST is FINAL and never births GET. Every final GET (matching success, Missing, failure or foreign result) uses FINAL handoff; failure/foreign result retains existing unresolved business semantics and permits only later GET-only retry after full retirement, not a second POST. Its successive result sequences cannot overlap. GET-only retry waits for prior full terminal/accounting retirement. Periodic ticks use the same rule; a tick spawning a report must acquire its separate report W credit before birth. If unavailable it retains only the publisher's established latest/pending payload, not a fresh operation per tick.

A completed report remains the real admission sentinel through synchronization notification, mode-specific conflict/unavailable notification, their revalidation/ack, and raw whole-Job terminal accounting. Validate identity/session/selection/foreground/mode after each callback. New pending reports cannot start before that sentinel retires; terminal completion alone does not remove it. Queue settlement notification likewise waits for its own full worker terminal and remains attached to the same W record. FINAL handoff lets that producer exit before notification/final ACK; the precharged root completion handler supplies terminal, eliminating per-settlement uncharged join children and duplicate settlement registrations. Create uses STREAM for pre-save validation and FINAL for its post-save last result; recovery uses FINAL for its last GET. Their same O retains exact stopping worker and terminal-dependent join/successor descriptors. The terminal-dependent successor descriptor finishes by consuming the exact whole-worker join fact and committing only the existing room owner's `afterJoin`/pending-creation/passive-recovery intent, then ACKs; it does not include a successor birth waiting on that same final ACK. No copied final payload, new waiting coroutine or extra result cell is retained. The existing holder's fixed dirty/control field later admits a separate successor from committed domain authority only after predecessor full terminal, final ACK/discard and physical disposition; successor must acquire its own existing O credit. Thus neither producer terminal nor final ACK depends on successor birth/retirement. An existing charged O join child, if retained by A, must fit the O inventory and cannot be awaited by the producer at FINAL handoff. Separate receipt completion is not a reducer. Terminal-first publisher report delivery remains unchanged: it is already terminal before notifications and needs no producer FINAL wait exception.

### Construction and shutdown conservation

Before each repository/reconciler/queue/playback/publisher call, R's declared slots are charged; selected factory loan persists across Stop/End. Each allocation registers to the passed construction owner **as soon as acquired**, before the next throwable constructor operation. Playback's actual constructor creates its subtree, invokes publisher factory, then registers an engine listener [S2]. The subtree/publisher/listener are owned; the engine is borrowed. A throwing `addListener` must either guarantee no registration or register its acquired remover in the construction owner before throwing. Publisher and queue constructors similarly register subtrees immediately. Return transfers the already-owned handles to installation/disposal; exceptions return no magical handle. A third-party factory unable to satisfy this allocation/exception contract is inadmissible. A throwing closer is not blindly retried; original charge is quarantined. The inspected `Call.awaitDecoded` cancels the Call on coroutine cancellation and closes responses in `response.use` [S6]; a cancelled worker's Job can nevertheless terminate before its transport callback. Each visible Call therefore retains a charged callback loan until the actual terminal callback returns and any response closes. Late responses attach to the original reserved response slot, never a new uncharged owner. Job terminal alone cannot recycle W/O/P/D or admit a successor physical call. Callback/response bookkeeping is neutral, whereas player disposal is affine. This narrow transport-ownership attachment also needs explicit scope approval if treated as excluded transport work.

Room `bodyJob/subtreeTerminal` and sibling `finalizerTerminal` are distinct cells. Normal Setup requires matching full subtree completion/join, successful required room-affine disposition and successful finalizer processing. Cancellation of the process parent before the finalizer body enters cannot prove a join: retain R/T and the detached tree. One completion registration on that exact tree is reserved as part of its R root Job+registration bundle before birth and installed outside G; it supplies the independent terminal fact. Tree and sibling finalizer use their own charged bundles, not a second registration on the same root. No replacement finalizer/cleanup Job is repeatedly born. Process cancellation permanently seals hosting; even later subtree completion only settles neutral facts, not Setup.

Completion callbacks record raw facts under G, request posting after unlock, and never reduce/dispose. If posting rejects, Main dies or process parent cancels, the holder claims each neutral receipt/ACK exactly once under G, then completes only that receipt outside G off-lane. For FINAL this also fixes/returns the finite handoff disposition without awaiting final ACK; for STREAM it settles the existing suspended sender as cancelled. Selected continuations still retain their loans until actual return; neutral discard is not successful execution. Ordinary pending results are explicitly cancelled/discarded; pure terminal/accounting facts may settle off-lane. Completed raw Jobs retain their cell and credit until that settlement owner consumes it; no unbounded completed-Job list. Domain publication, callback continuation and player/listener disposal cannot migrate to an arbitrary completion thread. Surviving authorized affinity disposal may succeed; otherwise retain original handles/charges, quarantine and seal across recreation until process exit. This is neither silent loss nor successful cleanup/Setup.

## 4. Progress: first service is not completed POST

Service quantum: one fixed pure state step, one immutable publication/callback, one external effect/birth/start/disposal call, or one terminal/receipt settlement. An external invocation includes its fixed G identity/activation preflight, followed immediately after unlock by that one call without dispatch/suspension; it does not subsume separate transaction reservation/commit or returned-handle attachment. Only the registered internal neutral completion handler may reenter G for fixed raw-fact bookkeeping; no supplied callback runs under G. Split call chains into descriptors; one quantum never loops over producers or waits for a worker. A quantum may block in an external call: strict deterministic wall-clock or POST progress is then impossible without assumptions.

Use a persistent round-robin ring of the 98 preallocated record slots; an owner has one ring position through sequence, publication, callback replacement and continuation updates. Cursor advances after service; insertion uses the existing vacant slot without resetting cursor; removal leaves a hole; blocked owners are skipped without moving the cursor backwards. Reuse is a new generation. No result/update creates another owner ahead of its victim.

K=4 counts **every fast-path selection**: ordinary reduction, no-op/repeated control, capacity notice, terminal notice, callback metadata update, and meaningful Stop/Start work unrelated to the victim. At four, serve one eligible ring owner and reset only after that owner quantum. Empty-ring service may clear the quota; insertion cannot. End/Stop admission invalidates affected unstarted effects immediately under G. Selected work validates causality before executing; it becomes cancelled rather than waits behind arbitrary control streams. Required Stop/End effect work is itself quota/ring service. Thus a disposal/terminal owner unrelated to current Stop→Start traffic still gets service; critical traffic is not a blanket exemption. Observer controls revoke still-unstarted effects before the next quantum.

With finite quanta, live posted consumer and continuously eligible victim, at most Emax=98 owner visits plus four intervening fast selections per visit give **B=(K+1)Emax=490 selector quanta to first service**. Causal invalidation ends eligibility for that effect, not unrelated disposal. This proof does not bound worker completion, paused barriers, queue-busy duration or an entire multi-stage command.

### ENDED grant and actual transport entry

Debt is one exact `(session, preparation)` fixed L record. Returning N capacity assigns the sole free slot to oldest eligible debt under G **before fresh producers**; a dirty bit outside N triggers service. Debt→Granted holds N; while real queue busy or W unavailable it retains that same grant without consuming ENDED or birthing work. Authoritative queue eligibility plus W is reserved/committed atomically under G as §2; success moves Granted→Consumed, transfers N to that queue operation, consumes ENDED once and clears debt. Stale/session/foreground/cancel/definitive rejection invalidates it, returning N exactly once. Metadata refresh preserves ID/grant; duplicate ENDED does not allocate; new preparation retires old debt; callback replacement updates its endpoint without repositioning or duplicating the grant. Capacity return then favors the next valid debt, never a notification turn or opportunistic producer.

Once a valid grant has queue/W capacity and remains eligible, the former four-stage shorthand is withdrawn. Matrix §5 explicitly counts **nine** owner quanta: G reserve with birth/registration charge; outside-G bounded post linkage; G commit; Pending publication; lazy root birth with activation preflight; G Job attachment; outside-G one completion registration; G registration-handle attachment; start with activation preflight. Reserve and commit are two distinct pure G phases, and linkage cannot hide callbacks/factories or lane waits. Therefore **9B=4410 selector quanta plus bounded worker-dispatch/transport-entry steps**, not 1960 or B, is the conditional conservative bound to actual POST entry. This bounds only this enumerated healthy route; a changed adapter requiring more selected stages must recount them before claiming it. Queue/W capacity and predecessor delays are separate assumptions; if they are unbounded there is no finite POST bound. External dispatch/callouts must return and the worker must be scheduled within declared bounds. No second POST follows an indeterminate result: the same worker owns GET reconciliation and any later GET-only retry. Neutral future oracles require positive actual birth/POST before producers stop, multiple owners/multi-results, and noninvalidating critical traffic alongside disjoint disposal.
