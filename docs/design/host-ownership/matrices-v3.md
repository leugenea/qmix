## 3. Finite topology inventory and pools (P)

A **record** is unique across phases; a borrowed reference does not create a second charge. W/O/T/P/D include pending value/terminal/receipt capacity, not extra N records for each result. N can point to a W/R loan while both remain charged: that overlap is explicit, not additive double counting of the same physical resource.

Every row has at most **1 value + 1 raw terminal + 1 ACK/receipt cell**, independent. `Cmax` counts simultaneous continuation descriptors; future STREAM phases reuse only after sequence ACK; FINAL never reuses the value cell before retirement. A physical slot is a declared ownership bundle, not one heap object: a Job bundle owns one Job plus at most one completion registration; a non-Job slot owns the exact named handle/Call/response/listener/channel; borrowed parent/engine/barrier references are not additional physical slots. Declared maxima are proposal ceilings, not measurement of the current application or third-party internals.

### End-to-end capacity amendment, not silently authorized

S4 has `Channel.UNLIMITED`; no finite host-only result ACK proves its internal retention. Proposed amendment is limited to existing `observe`/`startRefresh`/`collectEvents` and event-source owner handoff: explicit Command capacity **4**, at most three existing producer-held suspended commands (timer/event/refresh), explicit callbackFlow event capacity **64**, no added sender Jobs and no dropping additional authoritative commands. Existing SSE failed-offer behavior is not upgraded into delivery guarantees. Retain refresh Job ownership through full terminal fact before successor, rather than clearing ownership merely at result receive. Source-visible collection family owns six primary Job roles; eight reserved Job slots include context allowance. Transport/library-internal task bounds remain outside the declared envelope.

The 71 payload ceiling is 4+3+64; four O records conservatively reserve 284 even though only an observation family needs them. This amendment touches excluded repository ownership/backpressure; it requires owner-approved scope before implementation. Without it the **host** envelope is still specified, but pipeline-wide payload boundedness remains explicitly unavailable. Also proposed: the native callback L slot accepts one sequenced value; if a further non-backpressurable callback cannot be admitted while prior continuations own the cell, seal/cancel explicitly rather than conflate or lose an accepted event. This saturation/fail-closed policy requires owner decision and native viability proof, not assumed behavior preservation.

The narrow `RoomApiClient.awaitDecoded`/event-source attachment registers the visible Call/source and callback loan before enqueue/connect; callback response acquisition uses the existing reserved response slot. Worker Job cancellation is not proof that the underlying callback/response has finished. Return of a cancellation method alone never releases this loan. Only actual terminal callback/response disposition (or a verified no-callback/no-resource exception contract) can release it; otherwise retain/quarantine indefinitely in the same bounded record. Successor physical calls wait for this disposition. These allocation/terminal attachments are proposed scope, not an already-authorized transport rewrite. No extra Call-callback record is added to the numeric envelope.

### Aggregate counted envelope

98 = N64+W8+O4+T2+P2+D8+R2+L8 unique records. Cells/payloads ≤ 3×98 + 4×71 = **578**; typed continuation descriptors ≤8×98 = **784**. Conservative charged physical slots ≤ W8×6 + O4×16 + T2×1 + P2×4 + D8×4 + R2×10 + process-engine1 + process-parent-registration1 = **176**. The extra standalone registration corrects v2’s omitted source-visible parent subscription, not a new Job or record. Ordinary records borrowing owned physical slots do not add them again. The inequalities deliberately reserve per-pool headroom and include installed, selected, cancelling and quarantined states, not just queued work. Each Job slot includes at most one precharged completion registration (including its bounded callback/returned DisposableHandle); facts needed for close, terminal, queue settlement or subtree accounting are combined in that one handler. No growing terminal-handler list or extra registration/resource declared an alias to fit the formula. These are counted structural ceilings conditional on allocation contracts, not bytes, measured runtime totals or external-library bounds.
